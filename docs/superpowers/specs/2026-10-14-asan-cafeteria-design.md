# 아산 밥때 — 직원식당 통합 안내 서비스 설계 스펙

- 작성일: 2026-10-14
- 상태: 사용자 검토 대기
- 근거 자료: `reference/`(메뉴표 원본), `docs/research/2026-10-14-research-notes.md`(배경 조사, 출처 포함)

## 1. 목적과 성공 기준

서울아산병원 업무개선 AI 공모전에 출품할 산출물 두 가지를 만든다.

| 산출물 | 형식 | 성공 기준 |
|---|---|---|
| 상세 제안서 | `proposal/상세제안서.md` 원본 + `proposal/상세제안서.pdf` | 문제→해결→추진→효과가 근거(각주·출처)와 함께 12~15쪽 안에 읽히고, 구현 프로그램은 언급하지 않는다 |
| 구현 프로그램 | shadcn 기반 웹앱, Vercel URL로 제출 | 심사위원이 휴대폰으로 링크를 열어 아무 시각에나 점심 피크 상황을 재현·체험할 수 있고, 라이트·다크 모드를 지원한다 |

### 사용자가 정한 사항
- 심사 축: **업무개선이 핵심, AI는 가점.** AI는 2·3단계 확장으로 배치한다.
- 웹앱: **프런트엔드 프로토타입**(백엔드 없음, 모의 데이터), **웹 URL 제출**.
- 식권 인증 현황: **사원증 태깅 단말 + 모바일 식권·QR** → 로그 기반 혼잡 추정 가능.
- 제안서: 양식 자유, 표준 목차.
- 추가 기능 4종 모두 포함: AI 혼잡 예측·추천 시간 / 메뉴 비교·취향 추천 / 도시락 예약 연계·마감 알림 / 품절 현황·만족도 피드백.
- 식당 위치: 동관 B1F는 공식 자료로 확인됨. **서관·신관 직원식당 위치는 추정값**으로 두고 수정하기 쉽게 분리한다.
- 디자인: 아산 그린을 훨씬 많이, 오렌지는 아주 조금. 세련되고 현대적이며 "AI가 만든 티"가 나지 않게.
- 프로젝트 스킬(`.claude/skills/shadcn`, `migrate-radix-to-base`)을 적극 활용한다.

### 가정
- 병원 내부 시스템(아산넷, AMIS3.0, 태깅 로그)에는 연결하지 않는다. 링크는 바로가기(외부 이동)로만 표현한다.
- 알레르기·칼로리는 원본 메뉴표에 대부분 없으므로 앱에서는 "예시" 표기와 함께 넣는다.

| 참고문헌 | 각주로 쓴 출처 전체 |

### 2.2 작성 원칙
- 구현 프로그램(웹앱)은 언급하지 않는다. 화면이 필요한 곳은 서비스 개념도로 대신한다.
- 각 장에 표 또는 도식을 하나 이상 넣는다.
- 각주는 Markdown 각주 문법(`[^n]`)으로 쓰고, 조사 노트의 출처·접근일을 그대로 옮긴다.
- 조사 노트에서 `[미확인]` 또는 재인용으로 표시된 수치는 쓰지 않거나, 쓸 경우 "재인용"을 명시한다. "36% 과대평가" 같은 출처 불명 수치와 "국내 최초" 주장은 쓰지 않는다.
- 문장은 개조식과 평서문을 섞되 과장 표현을 피한다.

### 2.3 제작 파이프라인
- 원본: `proposal/상세제안서.md`
- 변환: Node 스크립트(`proposal/build/`)가 markdown-it + markdown-it-footnote로 HTML을 만들고, 공통 디자인 토큰을 쓴 인쇄용 CSS(`proposal/build/print.css`)를 입힌다.
- PDF: Playwright(Chromium)로 A4 출력. 표지는 딥 그린 전면, 본문은 흰 바탕. 쪽 번호와 머리글은 CSS paged media(`@page`)로 넣는다.
- 서체: Wanted Sans Variable(로컬 파일 임베드로 오프라인에서도 동일하게 렌더링).
- 명령: `npm run proposal:pdf` 한 번으로 md → pdf.

## 3. 구현 프로그램 (웹앱)

### 3.1 기술 구성
- Vite + React + TypeScript
- shadcn/ui, **Base UI** 기반(`npx shadcn@latest init --base base --preset maia --template vite`). maia를 고른 이유: 40px 이상 컨트롤, 둥근 카드, 넉넉한 여백 → 휴대폰 터치에 적합.
- shadcn 스킬의 DESIGN.md 흐름을 따른다: 앱 루트에 `DESIGN.md`(아래 3.6 토큰)를 두고 `tailwindCssFile`의 shadcn 변수에 매핑한다. 컴포넌트는 직접 만들기 전에 `npx shadcn@latest docs/search`로 확인한다.
- Radix 기반 코드가 들어오면 `migrate-radix-to-base` 스킬로 변환한다.
- 라우팅: React Router. Vercel 배포 시 SPA rewrite(`vercel.json`).
- 차트: shadcn `Chart`(Recharts).
- 상태: React Context + 작은 store 훅. 외부 상태관리 라이브러리 없음.

### 3.2 화면 구성 (모바일 우선, 하단 탭 4개)
데스크톱에서는 최대 폭을 두고 가운데 정렬하며, 넓은 화면에서는 2단으로 배치한다.

1. **지금 (홈)** — 확정안 A
   - 딥 그린 상단 영역: 건물 글자 타일(동·서·신)과 결론 한 문장("지금은 서관·신관이 바로 드실 수 있어요"), 보조 문장(동관 한산 예상 시각).
   - 그 아래 흰 시트: 현재 끼니의 배식 시간 막대와 오렌지 "지금" 표시선 → 식당 목록(행 단위, 카드 나열 아님). 각 행에 건물 타일, 식당 이름, 대표 메뉴 2개, 오른쪽 정렬된 상태 글자("줄 있음 / 약 8분"), 동관처럼 붐비는 곳은 시간대별 예측 막대.
   - 간편식 도시락 행(수령 마감 시각).
   - 운영 시간이 아닐 때: 다음 배식까지 남은 시간과 그 끼니의 메뉴를 보여준다.
2. **메뉴**
   - 상위 전환: 식당 / 테이크아웃 / 도시락. 끼니 전환: 조식(A·B) / 중식 / 석식(A·B) / 야식 / 이동식.
   - 중식은 동관과 서관·신관을 나란히 비교. 알레르기·칼로리(예시 표기), 별점, 즐겨찾기(하트), 품절 표시.
   - 테이크아웃은 그린존·오렌지존·퍼플존 구조를 그대로 반영한다. 존 이름과 "2PICK/3PICK/4PICK" 규칙은 글자로만 표기하고, 존별 색(초록·주황·보라)은 쓰지 않는다(오렌지 사용 제한 유지).
   - 도시락: 오늘 남은 수량(모의), AMIS3.0 예약 바로가기, 마감 알림 켜기.
   - 날짜 선택(이번 주).
3. **지도·운영시간**
   - 병원 건물 배치를 단순화한 SVG 모식도(서관·신관·동관·별관)와 식당 핀. 핀을 누르면 건물·층·찾아가는 법(추정 표기 포함).
   - 끼니별 운영시간표(평일·주말·공휴일 구분).
4. **알림**
   - 구독 항목: 대기 해소(식당별, 줄 있음→여유), 즐겨찾는 메뉴가 나오는 날, 도시락 예약 마감 전, 배식 마감 30분 전. 각각 `Switch`.
   - 오늘 식사 만족도(별점 + 남김 정도) 입력.
5. **검수 직원 화면** (`/staff`, 탭에는 없음)
   - 식당 선택 → 큰 버튼으로 "줄 있음 / 여유" 전환, 끼니별 품절 처리.
   - 입력은 같은 브라우저의 다른 탭에 즉시 반영(1단계 원터치 입력 시연).

공통 머리글: 서비스 이름, 시각, 테마 전환(라이트/다크/시스템), **시연 시간 조절**(Sheet 안 슬라이더와 요일 선택, "실시간으로 돌아가기").

### 3.3 데이터
- `src/data/restaurants.ts`: 식당 id, 이름, 건물, 층, 지도 좌표, 위치 신뢰도(`official` | `estimated`), 끼니별 운영시간 규칙.
- `src/data/menus/*.ts`: `reference/` 메뉴표를 옮겨 적은 이번 주 데이터(직원식당 주간, 오늘의 중식, 테이크아웃, 도시락). 메뉴 항목마다 인기도 가중치(모의), 알레르기·칼로리(예시) 필드.
- **요일 매핑**: 실제 날짜와 상관없이 오늘의 요일에 해당하는 저장 메뉴를 보여준다(언제 열어도 메뉴가 비지 않음). 화면에 "10월 3주차 메뉴 기준" 표기.

### 3.4 시간과 혼잡도 모델 (`src/lib/`)
- `clock`: 앱 전역 시뮬레이션 시계. 기본은 실제 시각, 30초마다 갱신. 시연 모드에서는 지정 시각으로 고정·진행.
- `hours`: 식당·끼니·시각 → `open | before(남은 분) | closed | holiday`. 자정을 넘기는 야식(23:30~01:00), 주말·공휴일 규칙을 처리.
- `queue`: 결정적 대기열 모델. 분당 도착 = 끼니 피크 곡선 × 메뉴 인기도 × 시드 고정 변동, 분당 처리 = 식당별 상수. 분 단위로 누적해 대기 인원과 예상 대기시간 산출. 같은 입력이면 항상 같은 결과.
- 상태 기준(예상 대기): 여유 < 2분, 보통 2~5분, 줄 있음 5~10분, 혼잡 ≥ 10분.
- `override`: 검수 직원 입력은 15분간 모델 값보다 우선. `localStorage` + `BroadcastChannel`로 탭 간 동기화.
- `recommend`: 남은 배식 시간의 예측 곡선을 계산하고, 예상 대기 3분 미만인 가장 이른 시각을 추천 시각으로 낸다. 홈 결론 문장은 "지금 가장 대기가 짧은 식당"과 "붐비는 식당의 한산 예상 시각"으로 만든다. 화면에 "모의 데이터 기반 예측 시연"을 표시한다.

### 3.5 개인 설정과 알림
- 즐겨찾기, 알림 구독, 별점, 테마는 `localStorage`. 접근 불가 시 메모리로 대체하고 기능은 유지.
- 알림 규칙 엔진은 시계가 갱신될 때마다 규칙을 평가해, 조건이 새로 충족될 때 한 번만 보낸다(중복 방지 키).
- 브라우저 알림 권한이 허용되면 Notification API, 거부·미지원이면 앱 안 토스트로 보내고 권한 설정 방법을 안내한다.
- 앱이 닫혀 있을 때 오는 푸시는 범위 밖(제안서에서만 다룸).

- 서체: **Wanted Sans Variable** 한 가지, 숫자는 고정폭(`tnum`), 한글 줄바꿈 `word-break: keep-all`.
- 모티프: 병원 길안내 사인물. 건물은 한 글자 타일(동·서·신, 8px 모서리)로 표시.
- 모서리 위계: 시트 22px, 타일 8px, 버튼·입력 maia 기본. 같은 반경을 모든 것에 쓰지 않는다.
- 금지 목록: ✨ 등 반짝이 아이콘, 이모지 아이콘, 그라디언트 장식, 같은 카드 반복 나열, 상태 배지 남발, 모든 제목 위 영문 대문자 라벨, 버튼 글자 뒤 화살표, 가운데점(·)으로 잇는 메타 문자열 남용.
- 움직임: 사용자 동작에 대한 반응(시트 열림, 상태 전환)에만. 자동 등장 애니메이션 없음. `prefers-reduced-motion` 존중.
- 상태는 색만으로 구분하지 않고 항상 글자로 함께 표기.
- 로고: 병원 로고는 쓰지 않는다(사용 시 디자인·콘텐츠팀 확인 필요). 서비스 이름은 글자로만 표기.

### 3.7 오류와 빈 상태
- 메뉴가 없는 날(예: 서관·신관 주말): `Empty`로 "주말에는 서관·신관 식당을 운영하지 않아요. 동관 메뉴 보기" 안내와 이동 버튼.
- 알림 권한 거부: 토스트와 함께 브라우저 설정 경로 안내.
- 저장소 불가: 조용히 메모리로 대체, 설정 화면에 "이 브라우저에서는 설정이 저장되지 않아요" 표시.

### 3.8 테스트
- Vitest 단위 테스트: `hours`(야식 자정 넘김, 주말·공휴일), `queue`(결정성, 상태 경계값), `recommend`, 알림 규칙(중복 방지), 요일 매핑.
- Playwright 스모크: 탭 4개 이동, 다크 모드 전환, `/staff` 입력이 다른 탭 홈에 반영, 시연 시간 조절로 상태 변화, 모바일 폭(390px)에서 가로 넘침 없음.
- 빌드 검증: `tsc -p tsconfig.app.json --noEmit`, `vite build`, 콘솔 오류 없음.

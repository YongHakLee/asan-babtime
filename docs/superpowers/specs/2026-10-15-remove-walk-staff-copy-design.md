# 밥타임 v3.1 — 근무 건물·도보 시간 제거, 검수 직원 화면 문구 정리 설계 스펙

- 작성일: 2026-10-15
- 상태: 사용자 검토 대기
- 선행 스펙: `docs/superpowers/specs/2026-10-15-staff-v3-design.md` (이 문서에 없는 내용은 선행 스펙을 따른다)

## 1. 목적과 사용자 결정

| 항목 | 사용자 결정 |
|---|---|
| 근무 건물·도보 시간 | **웹앱과 제안서 모두에서 뺀다.** '이동+대기 추천' 기능 자체를 접는다 |
| 홈 추천 | 근무 건물 없이 **대기만 보고** 고른다(근무 건물을 정하지 않았을 때의 지금 규칙) |
| 검수 직원 화면 | 입력 후 **상태 상자 + 취소 버튼**. 직원에게 **'예측값'이라는 말을 쓰지 않는다**(만료 후 예측으로 돌아가는 동작은 화면에 드러내지 않음) |
| 모델 비교 문구 | 직원 화면에서 **뺀다**("모델도/모델은 … 봤어요"). 입력 순간의 모델 예측은 계속 저장해 `/ops/accuracy`가 쓴다 |
| 구현 방식 | 화면에서 숨기지 않고 **코드까지 지운다** |

성공 기준:
- 웹앱 어디에도 '근무 건물', '걸어서 N분', '도보'가 보이지 않는다. 홈 결론 문장은 대기만으로 정해진다.
- 제안서에 이동+대기 추천과 근무 건물 기준 도보 시간이 남지 않는다(설문 배경 문항 '근무 건물'과 문제 정의의 '이동하고 줄을 서는 몇 분'은 남는다). PDF가 다시 만들어지고 verify가 통과한다(12~16쪽).
- 검수 직원 화면에서 직원이 할 일과 지금 상태가 한눈에 읽히고, 취소 버튼이 무엇을 하는지 이름만으로 알 수 있다.
- 기존 검증 기준(단위·E2E·tsc·lint·build, 제안서 verify)이 모두 통과한다.

## 2. 웹앱에서 근무 건물·도보 시간 제거

### 2.1 지우는 것
- `app/src/lib/walk.ts`, `app/src/lib/walk.test.ts` — 파일 삭제.
- `app/src/components/home/WorkBuildingSheet.tsx` — 파일 삭제.
- `app/src/data/buildings.ts`의 도보 시간 표(`WALK_MINUTES`)와 그것만 쓰는 타입·주석. `BUILDINGS`(지도 배치)는 남긴다.
- `app/src/lib/prefs.ts`, `app/src/hooks/usePrefs.ts`의 근무 건물 설정(`workBuilding`)과 그 저장·검증 코드. 예전에 저장된 값은 읽지 않고 오류 없이 무시한다.
- `app/src/pages/Home.tsx`: '근무 건물' 칩과 시트, 식당 줄의 "걸어서 N분(추정)", `walk` prop.
- `app/src/components/home/HallDetailSheet.tsx`: "근무 건물에서 걸어서 N분(추정)" 줄.
- `app/src/lib/recommend.ts`: `homeHeadline(now, from?)`의 `from` 인자와 그 분기(도보+도착 대기 선택, "걸어서 N분, …" 문장, "걸어가면 모두 마감 뒤에 도착" 분기). 시그니처는 `homeHeadline(now: Date)`.
- `app/src/domain/types.ts`의 `BuildingId`는 지도가 쓰므로 남긴다. 근무 건물 전용 타입이 있으면 지운다.

### 2.2 테스트
- 근무 건물·도보를 다루는 단위 테스트(`recommend.test.ts`, `Home.test.tsx`, `prefs` 관련, `HallDetailSheet` 관련)는 지우거나 대기만 보는 경우로 고친다. 대기만 보는 기존 테스트는 그대로 통과해야 한다.
- `e2e/home.spec.ts`의 근무 건물 테스트를 지운다.
- 새 테스트: 예전 형식의 근무 건물 저장값(`babttae.prefs` 등 실제 키)이 남아 있어도 홈이 오류 없이 대기 기준 문장을 보여 준다.
- 문자열 검사: 렌더한 홈·식당 상세 시트에 "걸어서", "근무 건물", "도보"가 없다.

## 3. 제안서 수정 (`proposal/상세제안서.md`)

| 위치 | 바꾸는 내용 |
|---|---|
| 요약 핵심 기능 4번(19행) | 제목을 "평소 혼잡 패턴, 운영자 대시보드."로, 본문 첫 절("근무 건물에서 걸어가는 시간까지 더해 가장 빨리 먹을 수 있는 식당을 안내하고,")을 빼고 "요일·시간대별 평소 혼잡과 원산지를 미리 보여 준다."로 시작 |
| 기능 표(173행) | '이동+대기 총 소요시간 추천' 행 삭제 |
| 기능 설명(182행) | "이동+대기 총 소요시간" 항목 삭제 |
| 그림 2(190–238행) | 결론 예시 두 줄을 "지금은 서관이 가장 한산합니다" / "예상 대기 1분, 동관은 13시 15분부터 한산"으로. ① 설명 두 줄을 "식당 3곳의 예상 대기를 비교해" / "지금 가장 빨리 먹을 수 있는 곳을 먼저 말한다"로. 캡션에서 "근무 건물을 정하면 도보 시간을 더해 고른다" 문장을 뺀다("(표시 값은 예시)"는 남김) |
| 단계 계획 그림(375행) | "· 이동+대기 추천, 평소 혼잡 패턴" → "· 평소 혼잡 패턴" |
| 3단계 표(402행) | "예측 모델·오차(MAE) 점검, 이동+대기 추천, 혼잡 패턴" → "예측 모델·오차(MAE) 점검, 혼잡 패턴" |
| 남기는 것 | 설문 배경 문항(552행)의 '근무 건물', 문제 정의(45행)의 "식당까지 이동하고 줄을 서는 몇 분" |

- 구현할 때 본문 전체에서 `이동+대기`, `도보`, `걸어`, `근무 건물`, `건물 간`을 다시 찾아 위 표 밖의 언급이 있으면 같은 원칙(기능 설명이면 빼고, 배경·문제 정의면 남김)으로 처리한다. 기능 개수를 세는 문장("새 기능 3개" 등)이 있으면 숫자를 맞춘다.
- 제안서 규칙 유지: 구현 프로그램(웹앱·프로토타입·시연)을 언급하지 않는다. 문체는 기존 본문(한다체)을 따른다.
- 다시 만들기: 저장소 루트에서 `npm run proposal:pdf && npm run proposal:verify`. 쪽수 12~16을 지킨다.

## 4. 검수 직원 화면 (`/staff`)

```
입구 상황
지금 입구 상황을 골라 주세요          ← 입력이 없을 때만

[여유] [보통]
[줄 있음] [✓혼잡]

┌───────────────────────────────┐
│ 직원들 화면에 '혼잡'으로 보여요       │   ← 유효한 입력이 있을 때만
│ 12:33까지 유지돼요(13분 남음)          │
│ [ 선택 취소 ]                         │
└───────────────────────────────┘

품절 입력                              ← 그대로
```

- **입력이 없을 때**: 버튼 위(제목 아래)에 "지금 입구 상황을 골라 주세요". 상태 상자는 없다.
- **유효한 입력이 있을 때**: 버튼 아래에 테두리 있는 상자(둥근 모서리, 카드와 같은 토큰).
  - 첫 줄(굵게): "직원들 화면에 '{등급}'{조사} 보여요". 조사는 여유 → "로", 보통·줄 있음·혼잡 → "으로".
  - 둘째 줄(보조색): "HH:MM까지 유지돼요(N분 남음)". HH:MM = 입력의 화면 시각 `at` + 남은 시간(`entryRemainingMs`)을 서울 시각으로. N = 남은 분(올림, 지금 계산과 같음).
  - 버튼: "선택 취소" — `variant="outline"`, 상자 너비 전체, 높이 h-11. 누르면 확인 창 없이 지금 입력을 취소한다(`cancelStaffEntry`).
- **취소하거나 15분이 지나면**: 상자가 사라지고 "지금 입구 상황을 골라 주세요"가 다시 보인다. 따로 취소 문구는 띄우지 않는다.
- **같은 등급을 다시 누르면**: 지금처럼 새 입력으로 기록되고 15분이 새로 시작된다(상자의 시각이 갱신됨).
- **화면 읽기 도구**: 항상 있는 `role="status"` 영역 하나에서 글자만 바꾼다 — 입력 시 "{등급} 선택됨", 취소 시 "선택 취소됨". 같은 등급을 다시 눌렀을 때도 다시 읽히도록 한다(예: 같은 글자를 지웠다가 다음 렌더에 다시 넣기). 매분 바뀌는 남은 시간은 이 영역 밖.
- **직원 화면에서 없애는 것**: "모델도/모델은 … 봤어요" 비교 문구, "지금은 예측값을 보여주고 있어요", "입력을 취소했어요…" 문구, '예측값'이라는 낱말 전부.
- **그대로**: 4단계 버튼, 식당 선택, 품절 입력, 머리말("입구 상황을 누르면 직원들 화면에 바로 반영돼요. 15분 동안 유지돼요"), 저장 형식(`staffLog`, 입력 순간의 `model` 저장 포함).
- 색: 상태 상자에 등급 색을 쓰지 않는다(버튼이 이미 등급 색). 오렌지 금지.

### 4.1 테스트
- `Staff.test.tsx`: 입력 전 안내 문구; 입력 후 상자 두 줄(조사 포함, 여유는 "로"), "12:20" 입력 시 "12:35까지 유지돼요(15분 남음)"; "선택 취소" 뒤 상자가 사라지고 안내 문구가 돌아옴; `role="status"` 문구; 화면 어디에도 "예측값", "모델" 낱말이 없음. 예전 비교 문구 테스트는 지운다.
- `e2e/staff.spec.ts`: "입력 취소" → "선택 취소", `/에 입력, \d+분 남음/` 같은 예전 문구 검사를 새 문구("까지 유지돼요")로 바꾼다. 취소 후 홈이 모델 값으로 돌아가는 검사는 그대로 둔다.

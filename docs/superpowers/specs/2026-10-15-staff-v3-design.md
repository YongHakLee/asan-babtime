# 밥타임 v3 — 검수 직원 입력 4단계, 입력 기록, 예측 점검 화면 설계 스펙

- 작성일: 2026-10-15
- 상태: 사용자 검토 대기
- 선행 스펙: `docs/superpowers/specs/2026-10-14-babtime-v2-design.md` (이 문서에 없는 내용은 선행 스펙을 따른다)

## 1. 목적과 사용자 결정

검수 직원 화면(`/staff`)을 고도화한다. 목표 네 가지(입력 정보 확장, 시연 설득력, 현장 사용성, 기록과 확인)를 아래 결정으로 좁혔다.

| 항목 | 사용자 결정 |
|---|---|
| 입력 단계 | **4단계 원터치**: 여유 / 보통 / 줄 있음 / 혼잡. 화면 등급·제안서("4단계 수준")와 같다 |
| 예측 비교 | 직원 화면은 **입력 전에는 예측을 숨기고, 입력 후에만** 그 순간의 모델 예측을 보여 준다 |
| 현장 사용성 | **입력 취소**만 넣는다 (만료 임박 안내, 근무 식당 기억, 한 손 배치는 넣지 않음) |
| 기록과 확인 | 운영자 화면에 **입력 누락 표시**만 넣는다 (직원 화면 입력 기록, 세 식당 요약은 넣지 않음) |
| 저장 구조 | **A안**: 식당별 최신 값(`overrides`)을 **입력 기록 하나(`staffLog`)**로 바꾸고 모든 화면이 이것만 읽는다 |
| 예측 점검 | 운영자 실시간 화면이 아니라 **별도 주소 `/ops/accuracy`**의 기간 분석 화면. 그래프는 **핵심 수치 타일 + 시간대별 일치율** 두 가지 |
| 제안서 | 고치지 않는다 (이미 '원터치', '4단계 수준'으로 적혀 있음) |

성공 기준:
- 직원이 '혼잡'을 누르면 홈·운영자 화면이 모델 예측과 상관없이 '혼잡'으로 보인다 (지금은 2단계 입력이라 모델의 '혼잡'이 '줄 있음'으로 내려가는 문제가 있다).
- 입력 후 직원 화면에 그 순간의 모델 예측이 나오고, 취소하면 바로 예측으로 돌아간다.
- 운영자 화면에서 배식 중인데 유효한 직원 입력이 없는 식당이 눈에 띈다.
- `/ops/accuracy`에서 기간 일치율과 시간대별 일치율을 그래프와 표로 볼 수 있다.
- 기존 검증 기준(단위·E2E·tsc·lint·build)이 모두 통과한다.

## 2. 데이터와 계산 규칙

### 2.1 저장 형식 (`app/src/lib/override.ts`)

```ts
export interface StaffEntry {
  /** 취소할 때 가리킬 식별자 (crypto.randomUUID, 없으면 realAt+난수) */
  id: string
  hall: DiningHallId
  level: CongestionLevel // 'ok' | 'mid' | 'queue' | 'busy'
  /** 입력한 순간의 화면 시각(시연 시각일 수 있음), epoch ms. "HH:MM에 입력" 표기와 기간 집계에 쓴다 */
  at: number
  /** 입력한 순간의 실제 시각, epoch ms. 15분 유효 시간과 정리 기준에 쓴다 */
  realAt: number
  /** 입력한 순간의 모델 예측(직원 입력을 덧씌우기 전) */
  model: { level: CongestionLevel; waitMinutes: number }
  /** 취소했으면 그 실제 시각 */
  cancelledAt?: number
}
```

- 저장 키 `staffLog`(접두사 포함 `babttae.staffLog`)에 배열로 쌓는다. 입력 순서대로.
- 저장할 때 `realAt`이 2일(48시간)보다 오래된 항목은 지운다.
- 기존 `overrides` 키는 더 이상 읽지도 쓰지도 않는다. 남아 있어도 오류 없이 무시한다.
- 형식이 다른 항목(식당이 3곳 밖, level이 4단계 밖, 숫자 필드 누락)은 읽을 때 건너뛴다.
- 품절 기록(`soldout`)은 바꾸지 않는다.
- 동기화는 지금 구조(localStorage + BroadcastChannel)를 유지하고, 지켜보는 키를 `babttae.staffLog`, `babttae.soldout`으로 바꾼다. `subscribeOverrides`는 이름을 그대로 둔다(품절 구독에도 쓰이므로).

### 2.2 함수

| 함수 | 역할 |
|---|---|
| `addStaffEntry(hall, level, at: Date)` | 입력을 기록한다. `model`은 그 순간 `simulateQueue` 결과(직원 입력을 덧씌우기 전)로 채운다. 만든 항목을 돌려준다 |
| `cancelStaffEntry(id)` | 그 항목에 `cancelledAt = Date.now()`를 적는다. 없는 id면 아무것도 하지 않는다 |
| `getActiveEntry(hall)` | 그 식당의 마지막 항목이 취소되지 않았고 0 ≤ 실제 경과 < 15분이면 돌려준다. 아니면 `null` |
| `entryRemainingMs(e)` | 15분 − 실제 경과 (지금 `overrideRemainingMs`와 같음) |
| `staffEntriesOn(ymd)` | 그 날(서울, `at` 기준) 항목. 취소 포함 |
| `lastEntryOn(hall, ymd)` | 그 날 그 식당의 취소되지 않은 마지막 항목 |

- `getActiveEntry`는 "마지막 항목"만 본다: 마지막 입력을 취소하면 그 앞 입력이 아직 15분 안이어도 되살리지 않고 예측으로 돌아간다(직원이 기대하는 '취소 = 예측으로'와 같게).
- 모델 예측 계산은 `status.ts`의 `effectiveWait`에서 덧씌우기 전 부분을 `modelWait(hall, meal, at)`로 떼어 내 공유한다. 배식 중이 아닐 때 입력하면 `model`은 `{ level: 'ok', waitMinutes: 0 }`.

### 2.3 대기 계산 (`app/src/lib/status.ts`)

등급 범위: 여유 [0, 2), 보통 [2, 5), 줄 있음 [5, 10), 혼잡 [10, ∞) — `levelForWait`와 같은 경계.

직원 입력이 있으면 모델 대기를 그 등급 범위로 맞춘다.

| 직원 입력 | 결과 대기 |
|---|---|
| 여유 | 0분 (지금과 같음) |
| 보통 | `clamp(모델, 2, 4.4)` |
| 줄 있음 | `clamp(모델, 5, 9.4)` |
| 혼잡 | `max(모델, 10)` |

결과 `level`은 항상 직원 입력 등급, `source`는 `'staff'`. 위끝을 4.4·9.4로 둔 것은 화면 표기(`waitText`가 반올림)가 "보통, 약 5분"이나 "줄 있음, 약 10분"처럼 다음 등급의 숫자로 보이지 않게 하려는 것이다.

### 2.4 추천 시각 (`app/src/lib/recommend.ts`)

- 지금: '여유' 입력이면 지금을 추천, '줄 있음' 입력이면 입력이 끝날 때까지 추천하지 않음.
- 바뀐 규칙: 직원 입력이 있으면 지금 시점은 2.3의 결과 대기로 판단한다. 3분 미만이면 지금을 추천하고, 3분 이상이면 입력이 끝나는 시각(`at + entryRemainingMs`)부터 모델로 찾는다.
- 따라서 '보통' 입력은 모델이 2.5분이면 지금 추천, 4분이면 만료 뒤부터 찾는다.

### 2.5 함께 고치는 곳

## 3. 검수 직원 화면 (`/staff`)

```
[ 동관 ][ 서관 ][ 신관 ]          ← 지금과 같음

입구 상황
┌──────────┐┌──────────┐
│   여유   ││   보통   │
│ 2분 미만 ││  2–5분   │
└──────────┘└──────────┘
┌──────────┐┌──────────┐
│  줄 있음 ││ ✓ 혼잡   │
│  5–10분  ││ 10분 이상 │
└──────────┘└──────────┘
12:18에 입력, 13분 남음          [입력 취소]
모델도 혼잡(약 16분)으로 봤어요

품절 입력                         ← 지금과 같음
```

- **버튼**: 2×2, 높이 h-24. 큰 글자는 등급 이름, 작은 글자는 대기 범위("2분 미만", "2–5분", "5–10분", "10분 이상"). 누른 버튼은 그 등급 색(`status-ok`, `status-mid`, `status-queue`, `status-busy`)의 테두리와 옅은 배경(`/15`), 오른쪽 위 체크 아이콘. 오렌지 강조색은 쓰지 않는다.
- **다시 누르기**: 같은 버튼을 다시 누르면 새 항목으로 기록되고 15분이 새로 시작된다(지금 동작과 같음).
- **입력 전**: "지금은 예측값을 보여주고 있어요"만. 예측 등급·분은 보여 주지 않는다.
- **입력 후**:
  - 첫 줄: "HH:MM에 입력, N분 남음" + 오른쪽 `입력 취소` 버튼(ghost, sm).
  - 둘째 줄: 저장된 `model`로 비교 문구. 같으면 "모델도 {등급}({대기})으로 봤어요", 다르면 "모델은 {등급}({대기})으로 봤어요". 대기는 `waitText` 형식("약 16분", "대기 없음"). 조사는 등급 이름에 맞춘다: 여유는 "로"(예: "모델도 여유(대기 없음)로 봤어요"), 보통·줄 있음·혼잡은 "으로". 맞고 틀림을 평가하는 말은 쓰지 않는다.
- **입력 취소**: 확인 창 없이 바로 취소. 이후 "입력을 취소했어요. 지금은 예측값을 보여주고 있어요"(식당을 바꾸거나 새로 입력하면 사라짐). 취소의 되돌리기는 없다.
- **화면 읽기 도구**: `role="status"` 영역에서 "{등급} 입력됨", "입력 취소됨"만 읽는다. 매분 바뀌는 남은 시간은 그 영역 밖에 둔다.
- 머리말 문구는 그대로("입구 상황을 누르면 직원들 화면에 바로 반영돼요. 15분 동안 유지돼요").

## 4. 운영자 화면

### 4.1 `/ops` 변경

- **지금 상황 섹션의 식당 줄**(배식 중일 때 둘째 줄):
  - 유효한 직원 입력이 있으면: "직원 입력: {등급}, HH:MM" (4단계 이름).
  - 없으면 **입력 누락**: "직원 입력 누락, 마지막 입력 HH:MM" — 오늘 실제 입력이 하나도 없으면 "직원 입력 누락, 오늘 입력 없음". 이 줄만 `text-status-busy font-semibold`. 배지는 쓰지 않는다.
  - '마지막 입력'과 누락 판단은 **이 브라우저의 실제 입력만** 쓴다(모의 입력은 쓰지 않음). 점심 피크 시연을 처음 열면 세 식당 모두 누락으로 보이고, 직원 화면에서 입력한 식당만 누락이 풀린다.
  - 배식 전·종료 후·휴무는 누락으로 보지 않는다(지금 문구 유지).
- 섹션 설명에 한 문장 추가: "배식 중인데 15분 안의 직원 입력이 없으면 누락으로 표시해요."
- 화면 맨 끝에 `예측 점검 보기` 링크(`/ops/accuracy`, 시연 시각 `?at=` 유지).
- 시연 시간 시트의 운영자 화면 링크 옆에 같은 링크.

### 4.2 예측 점검 화면 (`/ops/accuracy`)

```
예측 점검
검수 직원 입력과 그 순간의 모델 예측을 비교했어요. 모의 데이터라 실제 모델 성능이 아니에요

[ 전체 ][ 동관 ][ 서관 ][ 신관 ]

등급 일치율        입력          모델이 낮게 봤어요
  76%             184건         15%
                                높게 봤어요 9%

시간대별 일치율
평일 중식, 30분 단위
100%┤
    │ ▇▇   ▇▇               ▇▇
 76%┼ ── ── ── ── ── ── ── ──      ← 기간 전체 일치율(점선)
    │ ▇▇   ▇▇   ▇▇   ▇▇   ▇▇
  0%┼─────────────────────────
     11:00 11:30 12:00 12:30 13:00 13:30 14:00 14:30
                                   [표로 보기]
```

**라우트와 진입**: `App.tsx`에 `ops/accuracy` 추가(AppShell 안). 탭에는 없다. `/ops`와 같은 머리글 구성.

**데이터 범위**
- 기간: 저장 주간(2026-10-12~18) 중 **시연 시각 이전**의 평일 중식. 오늘은 시연 시각까지만.
- 대상: 모의 입력 + 이 브라우저의 실제 입력(`staffLog` 중 기간 안, 평일 중식 배식 중에 넣은 것). 취소한 입력은 뺀다.
- 기간 안에 입력이 없으면(시연 시각이 2026-10-12 11:10 이전이라 모의 입력이 아직 없을 때. 10-18 이후에는 주간 전체를 보여줘요) 그래프 대신 "이 기간에는 비교할 입력이 없어요".

**모의 입력** (`app/src/lib/accuracy.ts`, 저장하지 않고 계산)
- 식당·날짜마다 평일 중식 창 안에서 11:10부터 20분 간격(동관 11:10–14:50, 서관·신관 11:10–13:50).
- 기준 등급은 그 시각의 모델 등급(`modelWait`). 직원 등급은 시드 고정 난수(`fnv1a(\`${hall}|${ymd}|${HH:MM}\`)`, `mockRating`과 같은 해시)로 정한다:
  - 그 식당 중식 피크(`queue.ts`의 peak) ±20분 안: 한 단계 높게 35%, 한 단계 낮게 5%.
  - 그 밖: 높게 8%, 낮게 8%.
  - 등급 범위 밖으로 넘치면 기준 등급 유지.
- 같은 시연 시각이면 언제나 같은 결과가 나온다.

**집계** (`accuracy.ts`)
- 일치: 직원 등급 = 모델 등급. 모델이 낮게 봄: 모델 등급 < 직원 등급. 높게 봄: 반대.
- 핵심 수치: 일치율(%), 입력 수, 낮게 본 비율(%), 높게 본 비율(%). 백분율은 반올림 정수.
- 시간대: 입력의 `at`을 30분 칸(11:00, 11:30, …, 14:30)에 넣는다. 칸마다 입력 수, 일치 수, 낮게 본 수, 높게 본 수. 필터가 '전체'면 세 식당 합.

**그래프 규칙** (dataviz 기준)
- 핵심 수치: KPI 줄. 일치율은 히어로 숫자(48px 이상), 입력 수와 낮게 본 비율은 보조 타일. 높게 본 비율은 낮게 본 비율 아래 보조 줄.
- 시간대별 일치율: 세로 막대, 계열 하나라 범례 없음. 막대는 아산 그린(primary) 한 색, 위끝 4px 둥글게, 막대 사이 2px 간격. y축 0–100%, 격자는 옅게. 기간 전체 일치율을 회색 점선 기준선과 직접 라벨("평균 76%")로. 오렌지는 쓰지 않는다.
- 표본이 적은 칸(입력 5건 미만)은 막대를 옅게(불투명도 40%) 하고 칸 수치 안내 줄에 ", 표본이 적어요"를 덧붙인다.
- 칸 수치: 막대마다 버튼(칸 전체 너비가 누름 영역). 마우스를 올리거나, 누르거나(터치), 키보드로 초점을 옮기면 그래프 아래 고정 안내 줄에 "12:00–12:30 일치 61%(23건 중 14건), 모델이 낮게 봄 7건"이 나온다. 아무 칸도 고르지 않았으면 "막대를 누르면 시간대별 수치가 보여요". Base UI Tooltip은 터치로 열리지 않아 툴팁 대신 이 방식을 쓴다.
- 표로 보기: 같은 수치를 `<table>`로(시간대, 입력, 일치, 일치율, 낮게 봄, 높게 봄). 버튼으로 펼친다.
- 다크 모드: 그래파이트 배경에 맞춘 막대·기준선 색을 따로 두고 `validate_palette.js --mode dark`로 대비를 확인한다.
- 구현: `app/src/components/ops/AccuracyBars.tsx`, `ArrivalBars`처럼 div 막대로 그린다(차트 라이브러리 없음). 필터는 `/staff`의 식당 선택과 같은 `ToggleGroup`(전체 포함 4칸), 고른 값은 `?hall=` 주소 값으로 둔다.

## 5. 테스트

- **단위**
  - `override`: 기록 추가·취소·만료, 마지막 항목 취소 시 앞 항목이 되살아나지 않음, 2일 지난 항목 정리, 형식이 다른 저장값 무시, 예전 `overrides` 키 무시.
  - `status`: 4단계 각각의 범위 맞춤(모델 값이 범위 안/아래/위).
  - `recommend`: '보통' 입력 + 모델 2.5분이면 지금, 4분이면 만료 뒤.
  - `accuracy`: 모의 입력의 재현성(같은 시각 같은 결과), 피크 부근 '낮게 봄' 비율이 그 밖보다 큼, 실제 입력 합산과 취소 제외, 30분 칸 집계, 빈 기간.
  - 화면: Staff(4버튼, 입력 후 비교 문구, 취소), Ops(누락 문구, 링크), Accuracy(필터, KPI, 표로 보기, 빈 상태).
- **E2E** (`e2e/staff.spec.ts`)
  - 직원 화면에서 동관 '혼잡' 입력 → 다른 탭의 홈에서 동관 '혼잡', 운영자 화면에서 동관 누락 해제.
  - 입력 취소 → 홈이 예측으로 돌아가고 운영자 화면에 다시 누락 표시.
  - `/ops/accuracy?at=2026-10-14T12:20` 열기 → KPI와 막대가 보이고 390px에서 가로 넘침 없음.
- 마무리: `app/`에서 단위·E2E·tsc·lint·build 통과, 다크 모드 스크린숏 확인.

## 6. 범위 밖

- 만료 임박 안내, 근무 식당 기억, 한 손 배치, 직원 화면 입력 기록, 세 식당 요약.
- 등급 교차표, 식당별 비교 그래프, 날짜별 추이.
- 분 단위 오차(MAE): 직원 입력이 등급이라 계산하지 않는다. 화면에서 MAE라고 부르지 않는다.
- 서버 저장·기기 간 동기화(지금처럼 같은 브라우저 탭끼리만).
- 제안서 수정.
